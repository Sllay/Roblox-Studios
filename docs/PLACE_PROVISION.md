# Place Provision — official API only

Do not store .ROBLOSECURITY, browser cookies, passwords or session tokens in GitHub, the agent context, or repository secrets. A browser session is not a scoped development key. If a cookie was exposed to a third-party script, revoke that session. Use the existing scoped ROBLOX_OPEN_CLOUD_API_KEY and Roblox Creator Dashboard permission settings.

Two different resources: Universe/Experience (the game) and Place (a map within it). The official Open Cloud universe reference documents reading/updating existing universes and publishing existing places, not a supported create-new-universe endpoint for this API key. For a new independent experience, create the empty experience through an official Roblox UI, obtain Universe/Place IDs, then run Place Provision / enroll with record=true. The tool verifies the actual DataModel identity via Open Cloud, checks all mappings and production aliases, scaffolds the canonical game/place files, and records IDs. Existing IDs can be enrolled without recreating the game. This is a real local scaffold + remote identity verification, not remote universe creation.

For another Place inside an existing experience, Roblox documents AssetService:CreatePlaceAsync(name, templatePlaceID, description). It clones an owned template with copying enabled. Use a designated empty template Place, set templateForClone=true in its game.manifest.json entry only after review and enable copying in Roblox settings. Run clone-preview first; it inventories the experience, rejects duplicate names, confirms target identity and sync version. Clone requires explicit confirm_create=true and designated template; records returned ID before independent identity/owner verification and optional scaffold registration. Never clone the current test world pretending it is empty. No blind retry after ambiguous creation; inventory the universe first. This path's actual create capability remains untested until an owned approved template is provided.

Workflow: Place Provision (official API). inventory is read-only; enroll with record=false is read-only; clone-preview read-only; clone is a remote resource creation and staging-only. Git record uses normal non-force push. A key must authorize the selected experience. No automatic Get Model acquisition or legacy cookie automation. Official documentation: https://create.roblox.com/docs/reference/engine/classes/AssetService#CreatePlaceAsync and https://create.roblox.com/docs/cloud/reference/features/universes.
